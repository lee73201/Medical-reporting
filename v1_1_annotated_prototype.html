页面 01

登录/注册页

页面目标

完成用户身份验证，为 API 模式下的报告数据隔离提供登录态。

用户场景

新用户注册账号；老用户登录后查看自己的检验报告和 AI 解读。

核心功能

  • 邮箱密码登录
  • 姓名、邮箱、密码注册
  • 保存 JWT token
  • 切换 local 离线模式

交互规则

  • 登录成功进入首页
  • 注册成功自动登录
  • 401/token 失效自动退出
  • 密码至少 8 位且不超过 72 bytes

前置条件

API 模式下后端可访问；注册需邮箱未被占用。

后置结果

本地保存 `lab_auth_token` 和 `lab_auth_user`；后续 API 自动携带 Authorization。

数据字段/API

POST /api/auth/login；POST /api/auth/register；GET /api/auth/me；请求字段：email、password、name；返回：access_token、token_type、user。

验收标准

  • 成功登录后能进入 Dashboard
  • 注册重复邮箱提示错误
  • 无 token 访问 API 模式页面会回到登录页
  • 不在前端存储明文密码

页面 02

首页 Dashboard

页面目标

汇总最新报告的健康状态、异常指标和关键趋势。

用户场景

用户打开 App 后快速判断最近一次体检报告是否存在需要关注的指标。

核心功能

  • 患者信息展示
  • 总/正常/异常项目统计
  • 近期异常指标
  • 关键指标趋势摘要

交互规则

  • 统计卡片可展开/收起项目明细
  • 点击异常指标进入趋势分析并选中指标
  • 上传按钮进入报告录入

前置条件

存在至少一份报告；无报告时展示空状态和录入入口。

后置结果

用户可进入报告详情、趋势页或上传新报告。

数据字段/API

GET /api/reports，需 Authorization: Bearer token；local 模式读取 lab_reports_v2。字段：patient、reportType、hospital、date、items.status。

验收标准

  • 统计数量与最新报告 items 一致
  • 异常用红色，正常用绿色/灰色
  • API 模式只显示当前 user_id 的报告
  • 后端不可用时展示错误而非崩溃

页面 03

报告列表页

页面目标

展示用户历史检验报告，提供详情、AI 解读和趋势分析入口。

用户场景

用户想查看过往某次报告，或针对某份报告进行 AI 解读。

核心功能

  • 报告按日期倒序
  • 展示报告类型/医院/日期
  • 展示总项目和异常项目数
  • 上传入口

交互规则

  • 查看详情进入报告详情页
  • AI 解读进入 AI 页并高亮该报告
  • 趋势分析进入趋势页并默认选中首个指标

前置条件

用户已登录 API 模式，或处于 local 模式且本地有报告。

后置结果

设置 selectedReportId，用于详情、AI 解读和趋势上下文。

数据字段/API

GET /api/reports；字段：id、reportType、hospital、date、items[]、items.status。

验收标准

  • 列表只显示当前用户报告
  • 无报告时出现空状态
  • 所有按钮可跳转且不刷新整页
  • 不出现预约、支付、用药入口

页面 04

报告详情页

页面目标

展示某份报告的完整项目列表和每个指标的医学科普解释。

用户场景

用户需要核对报告数据、查看异常项目和理解指标含义。

核心功能

  • 报告基本信息
  • 患者信息
  • 项目数统计
  • 项目状态标签
  • 查看/收起解释

交互规则

  • 点击查看解释展开 explainLabItem
  • 异常指标使用柔和红色
  • 未收录指标显示通用解释

前置条件

从报告列表或其他入口设置 reportId；API 模式需有效 token。

后置结果

用户理解单项指标，可继续进入趋势分析或 AI 解读。

数据字段/API

GET /api/reports/{report_id}；items 字段：name、value、unit、refLow、refHigh、refText、refSource、status。

验收标准

  • 详情数据与列表点击报告一致
  • 每个项目显示值、单位、参考范围、来源和状态
  • 解释可展开/收起
  • 无字典项不报错

页面 05

趋势分析页

页面目标

基于历史报告展示某个检验项目的变化趋势和异常分析。

用户场景

用户关注某个异常指标是否持续偏高、是否逐步升高或降低。

核心功能

  • 指标选择
  • 折线趋势图
  • 参考范围背景
  • 时间节点点击详情
  • 名词解释/异常分析/历史记录 tabs

交互规则

  • 点击图表点显示日期、医院、值、状态和较上次变化
  • 历史记录可进入报告详情
  • 数据不足时显示提示，不误判趋势

前置条件

至少存在一份包含当前指标的报告；多点数据用于趋势判断。

后置结果

用户获得指标历史变化认知，可跳转原报告核对数据。

数据字段/API

GET /api/reports 后前端聚合同名项目；字段：report.id、date、hospital、reportType、item.name、value、unit、refLow/refHigh、status。

验收标准

  • 单点数据不显示“逐步升高/降低”
  • 上次数值为 0 时百分比显示“暂无”
  • 节点点击区域适合移动端
  • tabs 内容真实切换

页面 06

AI 健康助手页

页面目标

提供报告结构化 AI 解读和基于当前报告的健康问答。

用户场景

用户看不懂指标含义，希望用自然语言询问某项指标或整份报告。

核心功能

  • AI 解读/AI 对话模式
  • 当前报告上下文卡片
  • 快捷问题
  • 聊天记录 localStorage 保存
  • AI 不可用 fallback 本地规则

交互规则

  • 发送问题优先调用后端 AI
  • 失败则显示本地规则生成
  • 涉及用药/诊断不直接给处方
  • 所有 AI 输出包含免责声明

前置条件

存在当前报告；若无报告显示空状态并引导录入。

后置结果

生成回答并保存聊天记录；回答标记 AI 生成或本地规则。

数据字段/API

POST /api/ai/interpret；POST /api/ai/chat；请求携带 report、question、messages。失败返回 ok:false、fallback:true、error。

验收标准

  • AI 可用时显示 AI 生成
  • AI 不可用时 fallback 不崩溃
  • 回答引用数值、单位和参考范围
  • 必须出现“AI 仅供健康科普参考，不构成诊断或治疗建议”

页面 07

Profile 我的页面

页面目标

展示当前登录用户、数据模式、后端/AI 状态和开发者调试工具。

用户场景

用户确认当前账号和数据来源；开发阶段检查 API/AI 状态或迁移本地数据。

核心功能

  • 用户信息
  • 退出登录
  • local/API 模式切换
  • 检测后端/AI 服务
  • 同步本地到后端
  • 从后端拉取报告

交互规则

  • 退出登录清除 token/user
  • 切换模式不自动清空数据
  • 同步/拉取需要登录 API 账号
  • 清空报告不回退 sampleReports

前置条件

Profile 可在 local 或 API 模式访问；API 同步工具需有效 token。

后置结果

完成数据源切换、服务检测或数据迁移；用户可退出回到登录页。

数据字段/API

GET /api/health；GET /api/ai/health；GET /api/auth/me；POST /api/reports/import；GET /api/reports；localStorage keys：lab_data_mode、lab_auth_token、lab_auth_user。

验收标准

  • 显示当前用户邮箱
  • 退出后 API 模式回到登录页
  • 后端/AI 检测结果清晰
  • 不展示预约、支付、用药模块
